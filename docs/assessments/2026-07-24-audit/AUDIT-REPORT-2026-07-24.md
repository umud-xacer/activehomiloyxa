# Active Home — Implementation Gap Analysis (P-AUDIT)

**Date:** 2026-07-24
**Scope:** Backend (`apps/backend`), shared kernel/backbone, contracts, cross-cutting test suites. Frontend is factually noted but not audited in depth (see Section E).
**Method:** Read-only. Every quality gate was actually executed against the working tree as it exists on disk right now (not a predicted/expected result). Nothing was fixed, patched, or refactored as part of this audit.

---

## 1. Executive summary

Active Home's backend is **substantially real, not scaffolding**: all 13 bounded-context modules have genuine `domain/application/infrastructure/interfaces` content, a working composition root, 1,712 of 1,717 collected tests passing (99.7%), clean import-boundary enforcement (49/49 contracts kept), and — unusually for a codebase this size — extremely thorough, honest, per-module self-documentation of exactly what is and isn't done (every module's `README.md` has a "Known gaps" section; 12 of 13 modules have a dedicated `TRACEABILITY.md`). The engineering discipline described in CLAUDE.md (frozen contracts, ADRs for deviations, AIR-01 "don't touch another module as a side effect") is visibly followed in practice, not just stated.

That said, the project is **not currently shippable as-is**, for reasons that are narrow and fixable rather than structural: 7 of 10 CI quality gates fail right now for concrete, reproducible reasons (a lint-formatting drift on ~68 files, 31 missing type annotations confined to one test directory, 5 real test failures plus 3 errors, a mostly-cosmetic OpenAPI path-parameter casing mismatch in one module, an outdated image library with 20 known CVEs, and — as of this session — a frontend CI gate that will flip from "no-op" to "hard fail" the moment current work is committed, because `apps/frontend` is no longer a placeholder). Separately, and importantly for anyone reading this report's positive findings: **a large amount of the work described below — including most of the cross-cutting E2E/degradation/idempotency/authorization-matrix suites — is sitting uncommitted in the working tree**, beyond the last commit (`1062400`, "P-16"). None of it is in git history. If this checkout were lost, the repository's actual state (per `git log`) would look considerably less complete than what this report describes.

**CI workflow** — `.github/workflows/ci.yml` defines one job per gate, `qg01-lint` through `qg10-frontend`, exactly matching QG-01..QG-10 (confirmed by `grep -n "QG-0"` against the file, 10 distinct job names found). `qg03b-full-stack-e2e` is a real 11th job (nightly/merge-to-main only, brings up OpenSearch+MinIO in addition to Postgres/Redis) — not one of the ten numbered gates, an addition on top. Whether these are wired as *required* GitHub branch-protection status checks cannot be verified from a local checkout — **UNVERIFIED** (repository-settings concern, not a file on disk).

**Is `contracts/` actually frozen?** Yes, with a real, working amendment process — not just a status label. `contracts/README.md` line 3 states `STATUS: FROZEN (Task P-01)` and section "Amendment process" (line 143) describes the ADR-required path. This isn't theoretical: `docs/adr/` contains **6 real ADRs** (`0001`–`0006`), each amending the contract for a documented reason (e.g. `0004-ads-openapi-endpoints.md`, cross-checked against `ads/README.md`'s own account of the same event — the module's README says the repo owner explicitly directed "you can change the openapi.yaml, lets add needed APIs" and the ADR followed). **`shared_kernel/` contents** — verified by direct file listing and content read: `TypedId` base plus `UserId`, `ListingId`, `BusinessProfileId`, `MediaAssetId` (`typed_id.py`); `Money` (`money.py`); `LocalizedText` with all four locale fields `uz_latn`/`uz_cyrl`/`ru`/`en`, `frozen=True, extra="forbid"` (`localized_text.py`, confirms DEC-19 coverage and zero business behaviour — a pure Pydantic value object); `GeoLocation`, `ValidityPeriod`, `Locale` all present; `events/envelope.py` (event envelope); `outbox/port.py` (outbox abstraction). ### B. The thirteen modules

All 13 modules — `admin`, `ads`, `analytics`, `billing`, `catalog`, `configuration`, `identity`, `media`, `messaging`, `moderation`, `notifications`, `profiles`, `search` — have all four layer directories (`domain/`, `application/`, `infrastructure/`, `interfaces/`) present and non-empty (file counts captured directly per module; smallest is `admin` with 1 domain file, consistent with its documented "composition-only, owns no marketplace aggregate" charter). All 13 have a `README.md`. **12 of 13 have a `TRACEABILITY.md`** mapping FR/BRULE/I-nn ids to code and tests; **`configuration` is the one module without one** — it is also the oldest module (P-04) and, not coincidentally, the one module with real contract drift (below).

**Aggregates, domain integrity, repositories, use cases** — spot-verified across every module by reading domain/ class definitions, repository ports, and a sample of use-case tests; no anemic-model red flags found (setters, DTO-only validation, EAV tables, cross-aggregate "manager" classes). Representative, directly-verified examples:
- `catalog.domain.listing.Listing` — state transitions are guarded methods (`publish()`, `suspend()`, etc.), proven by `test_I05_illegal_transition_raises_and_leaves_state_unchanged` and `test_I05_every_transition_method_appends_exactly_one_record`.
- `billing.domain.entitlement.Entitlement` — `EntitlementFactory.activate_from_paid_order` is structurally the *only* constructor anywhere in the codebase, proven by `test_entitlement.py::test_I14_entitlement_has_exactly_one_constructor` — this is what makes I-14 true by construction, not just by caller discipline.
- `catalog.domain.exceptions.QuotaExceededError` docstring cites I-08 directly; `catalog/application/quota_service.py` raises it from `QuotaEnforcementService.check_can_create`, exercised by `test_listing_use_cases.py::test_I08_quota_exceeded_blocks_creation`.
- No EAV table exists: `catalog/README.md` states `apps/backend/tests/catalog/test_models.py`'s static parity check proves this directly against the actual SQLAlchemy models.

**OpenAPI operation coverage, both directions** — computed directly (not from any prior report) by loading `contracts/openapi.yaml` and the live `main.app.routes`, matching on `(method, path)`:

- 110 total spec operations; 107 implemented routes (excl. `/health`, `/ready`, introspection).
- **18 spec operations have no implementing route**: 3 are `Business Profiles` (`addTeamMember`/`listTeamMembers`/`removeTeamMember` — genuinely unimplemented; `profiles/README.md` documents exactly why, see Gap Backlog G-011); the other 15 (`GET/POST /admin/config/...` ×13, `GET /categories/{categoryId}` ×1, `GET /categories/{categoryId}/form` ×1) are **false-positive gaps**, not missing implementations — see next point.
- **15 implemented routes are "undocumented" per QG-06's drift check** — and cross-checking these against the 15 "missing" `configuration`/`categories` operations above shows they are the *same routes*: `configuration`'s router registers path parameters in snake_case (`/admin/config/{entity_type}`, confirmed by reading `configuration/interfaces/routers.py`) while `contracts/openapi.yaml` spells the identical route in camelCase (`/admin/config/{entityType}`). FastAPI route matching never uses parameter names, so these routes work correctly at runtime — this is a **string-comparison artifact in the drift checker**, not a functional gap. It still makes QG-06 fail as scripted (Section G), and it is real, uncorrected technical debt in `configuration`, the one module lacking a `TRACEABILITY.md`.

**Events published/consumed, idempotent consumers** — verified against `contracts/events/*.py` (one file per emitting context, all present) and each module's own event-projection tests. Idempotency is proven structurally, not assumed: `test_I23_*_is_idempotent` (analytics, 8 event types), `test_dispatcher_idempotency.py` (backbone, 2 tests), and per-module `ProcessedEventRow`/`idempotent_consume` usage confirmed by direct grep across `infrastructure/event_projection.py` files. Several documented, real gaps exist in the *wiring* (not the logic) of consumers — see Gap Backlog G-010 (media's outbox has no live dispatcher; several built-and-tested handlers are simply never attached to one in `composition_root.py`).

**Migrations** — every module has an `alembic.ini` and `versions/` directory; all 13 apply cleanly to a fresh, empty database (verified directly: created all 13 schemas by hand since no seed script exists yet — matching CLAUDE.md's own statement that `db-migrate.sh`/`db-seed.sh` "don't exist yet" — then ran `alembic upgrade head` per module; all 13 succeeded with zero errors after schema creation). Detailed per-table/per-index conformance to the Physical Database Design document was not exhaustively re-derived column-by-column for all 13 schemas (that would require a line-by-line diff against a 2,835-line document per module); spot-checks (`catalog`'s migration docstring explicitly cross-references DM-02/Physical DB Design's "no GIN index on `attribute_document`" rule and states it was hand-written, not autogenerated, specifically to honor that) show the same discipline holds. Full column/index-level re-verification against the Physical DB Design for all 13 schemas is **UNVERIFIED** at that granularity within this audit's time budget — flagged as a follow-up, not asserted DONE.

**Tests / coverage per module** — full-suite coverage run (Section G): 88.07% overall, 98.89% aggregated across every `domain/`+`application/` file, and `tools/check_domain_coverage.py` confirms directly: *"no domain/application file is below the 90% floor"* (exit 0, run directly). Per-module test counts self-reported in each `TRACEABILITY.md`/README are consistent with what `pytest --collect-only` shows for that module's directory (spot-checked for `identity`, `moderation`, `notifications` — counts match within a handful of tests, consistent with minor drift since those READMEs were last updated).

**Import boundaries vs. SAD** — `tools/importlinter.cfg` encodes the SAD's module table directly (leaf-free `configuration`, near-leaf `search` importing only `shared_kernel`+`configuration`, `billing`↔`catalog`/`profiles`/`ads` no-cycle, nothing imports `admin`/`analytics`/`notifications`, Clean Architecture layering per module, DIP for `infrastructure/`). **All 49 contracts KEPT, 0 broken** — run directly, this is the single cleanest gate in the whole audit.

### C. Invariants I-01…I-24

**Full table in `INVARIANT-COVERAGE-2026-07-24.md`** (required separate deliverable). Headline finding, important enough to state here too: **the `test_I<nn>_*` naming convention is heavily overloaded across this codebase.** CLAUDE.md's own naming-convention table implies `test_I<nn>_*` maps 1:1 to the Domain Model's global I-01…I-24 (its own worked example, `test_I08_quota_exceeded_refused`, does exactly that). In practice, at least four *different, unrelated* local numbering schemes reuse the identical `test_I<nn>_` pattern: per-module `test_boundary_import.py` files (their own "I-01..I-06" sequence about import-linter contracts, unrelated to the global list), `backbone`'s own infra-invariant numbering (I-09 through I-17 in `backbone/tests/`, about outbox atomicity/schema roles/migration safety/logging redaction — again unrelated), `shared_kernel`'s own VO-equality numbering, and `search`'s extensive internal cross-script-matching numbering (I-08 through I-16+, about digraph/apostrophe normalization, not the global invariants of the same number). A blind `grep test_I08_` across the repo would return several results for *different* modules' *different* local invariant #8, only one of which is the actual global I-08. **All 24 global invariants were individually content-verified** (not number-matched) by reading the Domain Model's exact statement and locating a test that actually asserts that statement's content, in the module the Domain Model's own "Scope" column assigns it to. Result: **all 24 have real, passing, content-matched coverage** — a genuinely positive finding — but roughly half are *not* literally named `test_I<nn>_*` after their true global id (see the coverage file for exactly which).

## 5. Risk assessment — what would break or be discovered late if shipped as-is

1. **Immediate CI break on next push**: QG-10 flips from no-op to hard failure the moment `apps/frontend/package.json` (already on disk) is committed, blocking every subsequent PR until real frontend CI steps are wired or the guard is updated — this would be discovered within minutes, not late, but it *will* block merges.
2. **Silent loss of a working critical-journey/degradation/authorization-matrix suite** if the current uncommitted working tree is ever discarded, reset, or lost (G-007) — the git history alone (`1062400`) does not contain any of `tests/e2e/`, `tests/degradation/`, `tests/idempotency/`, `tests/integration/`, or the consolidated `tests/authorization/` matrix. Anyone cloning from `origin` today gets a materially less-tested, less cross-verified system than this report describes.
3. **Performance is unmeasured, not just unmet**: `NFR-PERF-001`/`002` (search/interactive p95 targets) have no passing assertion — 2 of 4 benchmark tests currently fail outright rather than measuring and failing a threshold, so there is no current signal at all about whether the documented SLOs are met. This would surface as a production incident, not a code-review finding, if launched without addressing it.
4. **A known SQL-injection-shaped pattern in a security-sensitive file** (`backbone/persistence/schema_role.py`, used for per-module DB role/schema provisioning) is flagged by static analysis and not yet manually cleared as safe-by-construction in writing anywhere this audit found — low actual risk (role names are code-controlled per every call site checked) but worth a documented sign-off rather than leaving it as an open bandit finding indefinitely.
5. **An outdated image-processing library with 20 known CVEs** sits directly in the media-intake pipeline's dependency chain (Pillow, used for thumbnailing/EXIF-stripping on every uploaded image) — the exact kind of finding a real security review would flag immediately, and the fix is a one-line version bump.
6. **No tested backup/restore path exists** — if this were a production incident today, there is no evidence anywhere in the repo that a restore has ever been exercised, despite `NFR-BAK-001` calling for it.
7. **The main API service cannot currently be deployed via the documented container topology** — `docker-compose.yml` has no `api` service and no Dockerfile exists for it (only the separate realtime gateway is containerized), meaning "deploy the backend" today means running `uvicorn` directly on a host, not through the documented container path.
